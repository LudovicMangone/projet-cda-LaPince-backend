# 🗓️ Carnet de bord collectif — Sprint 0 — Conception

---

## 18/05/2026 — Sprint 0 / Day 1

### Lancement du projet

Début officiel du projet d’apothéose CDA et lancement du Sprint 0 dédié à la conception de l’application **La Pince**.

L’équipe réalise un premier échange afin de :

* présenter les profils et compétences de chacun,
* définir une organisation de travail,
* répartir les premiers rôles projet.

### Organisation et workflow

Décisions collectives :

* utilisation de GitHub Projects pour le suivi,
* mise en place d’un workflow Git avec branches `main`, `dev` et branches de features,
* Pull Requests obligatoires avant merge.

Création également d’un dossier `docs/` afin de centraliser la documentation du projet.

### Définition du projet

Premiers échanges autour du périmètre fonctionnel :

* gestion de dépenses de groupe,
* suivi budgétaire,
* système d’alertes,
* calcul des remboursements entre participants.

L’équipe commence à distinguer :

* les fonctionnalités du MVP,
* les évolutions possibles après la première version.

### Architecture envisagée

Premiers choix techniques validés :

* séparation front-end / back-end,
* architecture 3 tiers,
* React côté front,
* Node.js + Express côté back,
* PostgreSQL avec Prisma.

### Priorités du Sprint 0

Deux sujets sont identifiés comme prioritaires :

* le MCD,
* les wireframes.

---

## 19/05/2026 — Sprint 0 / Day 2

### Travail de conception

L’équipe avance en parallèle sur :

* le MCD,
* les wireframes,
* les premières réflexions d’architecture.

Un point collectif permet de :

* comparer les propositions,
* fusionner les éléments pertinents,
* converger vers une vision commune du produit.

### Validation du modèle de données

Le MCD est présenté à l’équipe pédagogique.

Suite aux retours :

* certaines cardinalités sont corrigées,
* les sous-catégories sont retirées du MVP afin de simplifier le modèle.

Le MCD est considéré comme stabilisé pour la suite du projet.

### Structuration du projet

Avancement sur plusieurs sujets :

* rédaction du cahier des charges,
* définition des User Stories,
* organisation GitHub Projects,
* consolidation des choix techniques.

### Décisions importantes

L’équipe valide plusieurs orientations :

* catégories fixes dans le MVP,
* application non collaborative dans un premier temps,
* budget facultatif,
* certaines fonctionnalités avancées déplacées hors MVP.

---

## 20/05/2026 — Sprint 0 / Day 3

### Avancement global

Validation progressive :

* des wireframes,
* de la direction graphique,
* des choix techniques,
* des premières routes API.

L’équipe continue également les échanges autour :

* des besoins utilisateurs,
* des parcours,
* de la cohérence globale du projet.

### Point avec l’équipe encadrante

Retour positif sur :

* l’avancement général,
* la cohérence des choix,
* la capacité de l’équipe à adapter le sujet initial.

### Travail de conception

Poursuite :

* des documents d’architecture,
* des modèles de données,
* des réflexions autour des relations métier.

### Arbitrages techniques

Décision collective :

* les types de projets deviennent des valeurs fixes,
* aucune gestion dynamique de ces types ne sera prévue dans le MVP.


---

## 21/05/2026 — Sprint 0 / Day 4

### Documentation et conception

L’équipe poursuit :

* la documentation technique,
* le dictionnaire de données,
* les réflexions autour des modèles de données.

### Réflexion métier

Une grande partie des échanges de la journée porte sur :

* la logique de répartition des dépenses,
* les balances entre participants,
* les remboursements.

Le sujet est identifié comme l’un des points techniques les plus complexes du projet.

### Point avec l’équipe pédagogique

Retours sur :

* les diagrammes de séquence,
* leur niveau de granularité,
* certaines bonnes pratiques de conception.

Discussion également autour du dark mode :

* choix de privilégier un stockage côté client via `localStorage`.

### Approche algorithmique

L’équipe commence à formaliser :

* les calculs de balances,
* les logiques de remboursement,
* les premières approches algorithmiques.

Une approche basée sur un algorithme glouton (*greedy algorithm*) est identifiée comme piste principale.

## 22/05/2026 — Sprint 0 / Day 5

### Organisation technique

Discussions autour :

* de la CI/CD,
* des workflows Git,
* des conventions de commits,
* des outils de qualité de code.

### Réflexion sur l’organisation du Sprint 1

L’équipe réfléchit à une organisation plus fluide pour la phase de développement :

* répartition front/back,
* découpage en petites étapes techniques,
* Pull Requests fréquentes,
* validations croisées.

### Qualité et bonnes pratiques

Point pédagogique autour :

* du responsive design,
* de l’accessibilité,
* de la sécurité,
* du RGPD,
* de la qualité web,
* des bonnes pratiques Git.

### Documentation projet

Consolidation de plusieurs éléments :

* architecture des repositories,
* conventions de nommage,
* organisation Git,
* documentation technique,
* workflows de développement.

### Fin du Sprint 0

Le Sprint 0 se termine avec :

* une architecture définie,
* un MCD validé,
* des wireframes stabilisés,
* une stack technique choisie,
* une organisation projet opérationnelle.

L’équipe est prête à démarrer le Sprint 1 dédié au développement.
